# 科技范式迭代：告别纯聊天大模型，读懂 JEV 结构化决策的底层变革

2026年9月，一个不会说话的模型在36小时内涌入了14万名开发者，Vercel上近13%的付费团队在第一天就接入了它。它不能写文章、不能聊天、连一句完整的句子都生成不出来，只返回几个数字和标签。但它创下了新模型上线首日采用率的历史纪录。这件事的意义不在于又多了一个模型，而在于**AI的物种分化开始了**：聊天模型继续服务人，决策模型开始服务程序。

JEV最容易被误解的地方，是把它当成“更小的LLM”或者“加了JSON模式的ChatGPT”。它不是。传统大模型即便开了结构化输出，底层依然是逐token自回归生成，程序拿到一段JSON之后还得校验格式、处理缺字段、猜测那个0.82到底是什么意思。JEV走的是另一条路：你给它一段状态和几个类型化问题，它直接在预定义的答案空间里返回概率分布，没有生成过程，没有需要解析的文本，没有“让我分析一下”的前缀。京东云那篇分析把这件事的本质说得很准：**“答案属于什么类型”成了模型接口的一部分，而不只是提示词里的要求**。

这个区别在工程上的后果是巨大的。普通大模型问一个问题要等三到三百秒，JEV的端到端延迟是七十到五百毫秒；普通大模型输出按token计费，JEV输出免费，输入每百万token只要零点零四二美元。更关键的是并行能力：同一份输入下问一个问题还是问一百个问题，耗时几乎不变，因为输出空间是预先定义好的，不需要逐个生成。这意味着过去因为“太慢太贵”而根本没进入考虑范围的场景——比如每一次工具调用前的路由判断、每一张工单的实时分流、每一个Agent动作前的安全确认——突然变得可做了。

但真正让我觉得这件事值得认真对待的，不是速度和价格，是**AI在软件系统里的位置变了**。过去两年大家习惯的模式是：把问题丢给大模型，让它写一段话，然后人读那段话，或者程序解析那段话。这个模式有一个隐藏的假设：AI的输出是给人看的，或者至少是给人设计的格式看的。JEV推翻了这个假设。它输出的东西不需要任何人读，置信度零点九一直接进阈值判断，大于零点八五自动处理，小于零点五转人工。TypeSafe把训练方法叫RLCD，优化目标不是“人类觉得这个回答好”，是“模型说自己有九成把握的时候，是不是真有九成的时候是对的”。校准，而不是讨喜。

这引出一个更深的判断：**聊天大模型和决策模型的分工，本质上是“系统二”和“系统一”的分工**。卡尼曼那套框架被用在这里很贴切。聊天模型负责慢思考：推理、规划、生成、解释。决策模型负责快判断：分类、路由、打分、拦截。一个客服系统收到用户消息，JEV在几百毫秒内判断该转给支付团队还是售后、愤怒程度几分、要不要立刻升级，然后把结果交给下游代码去执行；如果还需要一封安抚邮件，再把上下文递给擅长写作的大模型去生成。两件事本来就不该由同一个模型用同一种方式做。

当然，现在把JEV捧成“范式革命”还为时过早。独立测试显示它在中文客服场景的完整准确率大约六成四到六成五，和便宜的小模型相当，并没有碾压级优势。“零幻觉”的宣传也要打折看：置信度衡量的是模型自己有多确定，不等于客观正确率。它真正改变的不是“AI有多聪明”，而是**“AI的判断以什么形态进入软件”**。过去程序只能用if-else写死规则，或者从大模型的文本里抠JSON；现在程序可以直接拿一个带概率的类型化结果做控制流。这个变化不炫目，但它是从“AI辅助人”走向“AI作为系统组件”的那一步。

中化数智已经在内部平台完成了JEV的本地化部署，用在智能体选工具、工单分流、发票筛查这些场景上。企业端的动作比舆论场诚实得多：它们不关心范式，只关心什么东西能稳定地、便宜地、在毫秒级把判断交还给程序。JEV如果能把这件事做实，它就不需要说话。
